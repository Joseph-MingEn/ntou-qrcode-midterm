# 以 Python QR Code 連結本機互動網頁的實作與驗證

學號：0136C008　姓名：涂名恩

> 本檔保留原始整理及歷史紀錄；正式繳交版報告與 ZIP 見文末。兩台裝置的掃描及互動依使用者回報記載，兩張畫面分屬不同日期。

## 目的

網址若過長，在手機上逐字輸入容易出錯，也會增加分享網頁的時間。本作業以 Python 把公開網址及電腦上的本機網頁網址轉成 QR Code，讓使用者可以掃描連結，再用程式解碼圖片，比較是否與輸入一致。自行架設網頁除了觀察 QR Code 能否導向正確內容，也能記錄請求並檢查不同裝置在同一網路的連線情形。另比較容錯等級及標籤對圖片大小與讀取結果的影響。

## 3.1 執行環境

2026-10-30 電腦為 macOS 27.0.1、arm64、Python 3.14.6；qrcode 8.2、Pillow 13.0.0、opencv-python-headless 5.0.0.93（cv2 5.0.0）、NumPy 2.5.4。使用者回報的兩台裝置為 iPhone 13 Pro 與 iPad Air M6；掃描軟體與各自瀏覽器的具體資訊尚待確認。

## 3.2 QR Code 原理

QR Code 由深淺方形模組構成，version 決定模組格數：每邊為 17 + 4 × version。容錯等級 L、M、Q、H 影響資料冗餘；等級提高一般有較強的錯誤修復能力，但不能保證任意遮擋均可讀取。實際 H 圖 version 3、29×29 模組；靜區不計入模組數。不同輸入可能選擇不同版本。

## 3.3 程式架構

`src/qr_web.py` 以 argparse 提供 make、decode、compare、serve；qrcode 編碼，Pillow 輸出圖片與標籤，OpenCV 解碼；http.server 提供 `site/index.html` 並將 HTTP 請求寫為 JSONL。`results/` 的 JSON 與 Markdown 分別保留執行資訊。網頁按鈕以 JavaScript 在頁面顯示回應，不上傳表單資料。

## 3.4 產生結果與容錯比較

| 等級 | version | 模組 | 像素 | PNG bytes | OpenCV 解碼 |
|---|---:|---:|---:|---:|---|
| L | 2 | 25×25 | 330×330 | 1498 | 相同 |
| M | 2 | 25×25 | 330×330 | 1476 | 相同 |
| Q | 3 | 29×29 | 370×370 | 1853 | 相同 |
| H | 3 | 29×29 | 370×370 | 1823 | 相同 |

[比較紀錄](../results/qr_compare_20261030_175958_844530.md)與[四張圖片](../images/compare/)；PNG 壓縮使檔案大小不必隨等級單調增加。這只是完整圖片的電腦解碼，不能推論所有損壞情況或手機可讀性。

## 3.8 錯誤與排除

實作環境中受限網路無法解析 PyPI，改用允許網路的安裝程序完成；在受限沙箱中自動伺服器測試無法綁定 loopback，允許本機連線後五項測試通過。另故意以白色中央區塊覆蓋 H 圖 259×259 像素並寫上 LOGO，[受損圖](../images/qr_logo_too_large.png)在 OpenCV 找不到定位點、解出空字串。因該遮擋破壞大量模組與定位結構，改用靜區外文字標籤，電腦解碼成功；尚未以手機測受損圖或標籤圖。記錄詳見[手動測試](../results/手動測試紀錄.md)。

## 3.9 結論與心得

電腦端已實際產生並比對 QR Code，四種容錯等級的完整圖均可由 OpenCV 讀取；本機網頁也已在電腦瀏覽器顯示身分與互動結果。不同版本與 PNG 壓縮會影響實際尺寸及檔案大小；大面積遮擋則可能破壞辨識。使用者已回報兩台裝置掃描本機頁並成功互動；兩張畫面的裝置型號也已由使用者確認，遮蔽後證據及其限制見文末。
